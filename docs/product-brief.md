# 第一版产品范围与开发前决策

更新日期：2026-09-14。本项目采用开源模式，面向 Windows 普通用户的误删文件恢复任务。本文作为当前产品范围；研究报告中的 exFAT/JPEG 专项保留为后续技术实验，不作为首版产品的前置目标。

## 已确定的定位

帮助普通 Windows 用户找回误删、且无法从回收站直接还原的重要文件。主要用户是办公、学习和个人电脑用户；优先照顾文档、照片及包含这些文件的文件夹。

第一版覆盖四类用户任务：

1. 清空回收站后找回文件。
2. 使用 Shift + Delete 删除后找回文件。
3. 误删整个文件夹后找回其中内容。
4. 删除移动存储中的文件，回收站中没有可用副本。

技术优先级为 NTFS 误删恢复。移动存储是否可以处理，由其文件系统和实际支持范围决定；不能因为设备是 U 盘就自动声称支持所有文件系统。优先文档/照片指测试和预览范围，不应人为限制元数据路径可正确提取的其他文件。

## 可以直接采用的开发默认值

- 第一主机目标：Windows 11 x64，中文桌面界面。
- 本地处理，核心扫描与恢复免费，不设置恢复容量收费门槛。
- 不要求账号；第一版恢复流程不依赖上传文件或云端服务。
- 文件系统元数据恢复优先，内容扫描作为补充；尽可能保留原文件名和目录。
- 开发从可复现的 NTFS 镜像测试开始；最终用户流程提供磁盘/原位置选择，镜像制作不作为普通用户必经步骤。
- 界面、索引、任务管理与解析库由开发侧选型，不要求用户逐项选择。
- 扫描只读源数据；恢复结果、缓存、日志和索引写入安全的目标位置。真实设备流程需识别物理源盘并处理系统持续写入。

以上属于工程默认值。0.2.0 已实现 NTFS 桌面扫描、预览、筛选、导出、回收站关联、删除目录遍历、Windows 卷入口及便携打包。实际 Qt 流程与真实镜像已验证；Windows 启动、卷访问及清空回收站效果仍待真机验收。开发顺序为先完成桌面测试版，再做真机验证。实际能力以[开发说明](development.md)为准。

## 用户操作流程

1. 选择文件原来所在的位置或磁盘。
2. 可选填写记得的名称或文件类型；记不清也能开始查找。
3. 扫描并展示候选文件，保留原位置等可获得的信息。
4. 按名称、类型、路径等筛选，预览可支持的内容。
5. 选择需要保存的文件与目标位置，完成免费导出。
6. 告知实际保存结果、已做检查和已知缺失；没有找到或无法恢复也给明确状态。

原路径与名称只在有足够证据时恢复。需要推断的字段与内容扫描生成的名称应明确区分。清空回收站是需要独立测试的真实 Windows 操作，不能只用普通目录删除代替。

### 清空回收站的实现要点

移入回收站后，内容通常以 `$R…` 名称保存，配套的 `$I…` 索引记录原路径、大小与移入时间；清空后索引也会被删除。因此需要尝试恢复并关联残留的索引与内容，不能将列出当前回收站目录视为已经支持清空恢复。关联需结合所在卷、用户 SID 目录、名称后缀及可用证据，防止记录重用造成错误匹配。索引或其他路径证据不足时，允许恢复内容，但不能承诺原名称与原目录。[Rifiuti2 维护者技术说明](https://abelcheung.github.io/rifiuti2/technical/)、[RBCmd 固定版本解析代码](https://github.com/EricZimmerman/RBCmd/blob/756498f9b5e94327abe5398b19435b7142f7265c/RecycleBin/DollarI.cs#L17)

测试方案分别保留原始、移入回收站、清空及后续写入阶段的镜像；覆盖中文名称、不同目录同名文件、整目录删除、索引/内容单侧缺失与记录重用。独立统计内容一致性、原名称/路径准确性和错误关联数，恢复为 `$R…` 的结果不计入原名恢复。格式解析及关联已做自动测试，隔离 Windows 样本生成脚本已编写；真实清空回收站后的端到端恢复仍待真机验证，完整测试方案尚未全部实现。

## 首版验证标准

| 验证项 | 通过条件 |
| --- | --- |
| 四类删除任务 | 使用已知原件、预先登记的删除目标和正常 Windows 操作生成测试材料，逐项验证实际导出结果 |
| 文件内容 | 测试原件与输出比较长度及 SHA-256；结构有效、可预览和原件一致分别记录 |
| 名称与目录 | 在残留信息足够的样本上核对原名称、原路径和目录关系；缺失时不伪造确定结果 |
| 负面样本 | 对覆盖、损坏、缺失和不支持的情况保留正确状态，不能把空文件或错误拼接标成完整 |
| 源数据保护 | 冻结镜像扫描前后内容不变；真实设备另验证挂载、缓存、日志和目标盘策略 |
| 操作稳定性 | 取消、权限失败、目标满盘、异常候选和中途退出有明确结果，不覆盖已有导出文件 |
| 用户价值 | 用户能够找到指定目标并免费保存；记录任务耗时与人工筛选负担 |

Windows 真机验证、依赖许可核对和安装包/签名准备安排在对应的设备与发布阶段。它们影响该阶段交付，不阻塞前期基于镜像的恢复引擎开发。

## 当前交付与后续顺序

1. 交付完整 NTFS 桌面测试版与可独立运行的 Windows x64 便携包，附源码、许可、使用说明和验证工具。
2. 之后用 Windows 11 真机验证启动、权限、卷访问、同盘拦截及真实删除场景，按独立原件形成逐目标结果。
3. 根据失败样本补足元数据恢复与操作问题，再增加内容扫描及其他文件系统。
4. 基础任务可靠完成后，用独立对照实验决定是否投入 exFAT/JPEG 等专项重组。

用户目标是找回误删的重要文件。当前优势来自免费导出、清楚的本地流程、可审计结果和开源实现。“超过竞品”的算法优势需要公平实测证明，不作为开始开发基础产品的前提。
