# 隔离 NTFS 样本的自动验收

开发日期：2026-09-14。接续 Windows 镜像验证，为既有样本生成脚本补上四阶段扫描、恢复、原件核对和汇总报告，并构建包含新入口的本地便携包。当前会话不是管理员，真实 VHD 生成和清空回收站实验仍未执行。

## 本轮实现

- 新增 `python -m recovery_core validate-fixture`。扫描前检查完整生成状态、样本 ID、原件副本长度与 SHA-256、镜像摘要和几何参数，并按删除场景核对阶段目标，拒绝缺漏、重复、混入保留对照及路径越界。
- 核对后冻结各阶段参考清单，恢复后端只读取镜像与几何参数。内容、名称、目录和路径分别统计，缺少回收站 `$I` 证据时不能从原件清单中补出名称。
- 四阶段目标数为 0、4、4、8：原始阶段记为 `baseline`，零目标不显示 100%。8 个不同删除目标与跨阶段 16 次验证分别记录。
- 阶段失败保留错误并继续后续阶段。扫描或导出取消时保留已完成结果及当前导出报告，尚未执行的阶段标记为 `not_run`。
- 新增 `Invoke-RecoveryValidation.ps1`，先检查运行时，再串联隔离样本生成与验收。每轮只使用新建目录，保存材料、恢复结果及 `workflow.json`。脚本要求管理员会话；已有样本的 Python 验收命令可在普通用户下运行。
- 便携构建器加入新核心模块和串联脚本。[命令与报告使用说明](../windows-testing.md)

## 实际验证结果

| 检查 | 结果与范围 |
| --- | --- |
| 新增自动测试 | 23 项通过；覆盖正常、空文件、中文及同名文件、损坏/不完整材料、错误内容、缺失回收站索引、来源变化、失败继续及扫描/导出取消 |
| 完整自动套件 | 131 项中 129 项通过、2 项因 Windows 符号链接权限跳过；无失败或错误，Qt 用例全部执行 |
| 真实 TSK 与原生桌面 | NIST 镜像的扫描、预览、导出和字节核对通过；参考摘要来自删除后镜像指定区域，不是独立删除前原件 |
| Windows 查询与脚本解析 | 只读卷枚举通过；包括新串联脚本在内的 PowerShell 脚本均通过 Windows PowerShell 5.1 解析检查 |
| 普通用户启动串联脚本 | 被 `ScriptRequiresElevation` 拒绝，退出 1，未创建任何本轮工作目录；没有执行 VHD 生成 |
| 本地便携包完整性 | 393 个清单文件匹配；147 个 PE 文件位数与依赖检查通过 |
| 包内运行时 | Python 3.13.12、Qt 与 TSK 启动通过；新 CLI 帮助和模块加载通过，确认模块来自包内 `src/` |
| 包内四阶段验收 | 使用受控测试后端和合成字节材料，16 次内容及路径核对全部匹配；没有使用真实 Windows 删除镜像 |

新增测试的后端列表和提取字节由测试程序独立提供，扫描、导出及原件校验使用实际核心代码。受控材料只有用于几何检查的 NTFS 标记，不是 Windows 生成的完整文件系统。上述测试验证验收逻辑，不构成真实清空回收站恢复率的证据。

完整验证完成后，复查时扩展了取消用例，补测“导出已保存部分文件后取消”的分支；随后重新运行全部 23 项样本验收测试通过。生产代码未因此改变。

本地证据保留于以下位置，均在 Git 忽略的 `artifacts/` 中：

- `fixture-development-windows/`：完整自动套件、Windows 查询和真实 Qt/TSK 镜像演示的日志、截图及报告。
- `fixture-wrapper-nonadmin.json` 与 `.log`：普通用户入口拒绝检查。
- `fixture-package-pe-audit.json`、`fixture-package-checks/`：便携包完整性、依赖、启动和 CLI 检查。
- `fixture-package-controlled-smoke/`：包内运行时的受控四阶段材料与逐目标验收报告，报告明确标注没有执行 Windows 样本生成或真实 TSK 样本恢复。

本地构建产物为 `dist/ShiHui-0.2.0-fixture-validation-windows-x64.zip`，118,915,233 字节，SHA-256 为 `77d6f3835fd57f7d50a36ccce6d6cf13ae775f6d3dc970d439bf914d96f0347d`。本轮没有发布新 GitHub Release；原始 0.2.0 发布包不含新增入口。

## 剩余验收

下一步在管理员 Windows 11 测试会话中运行串联脚本，检查 diskpart/Storage、Windows Shell 回收与清空，以及真实四阶段镜像在 TSK 中的恢复表现。生成失败或存在未匹配目标时，保留材料与报告，依据实际失败补充修复。

UAC、原始卷读取、真实源/目标隔离及不同物理介质的测试仍按产品计划进行。本轮没有改变已支持的文件系统或新增内容扫描，不产生超越竞品的结论。
